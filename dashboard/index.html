The agent never holds the wallet

It holds one key of a Squads 2-of-2 multisig. The owner-side gatekeeper holds the other and votes only after the policy passes and the on-chain proposal is independently verified. The policy engine is plain code, so no model can talk its way past it.

If a poisoned page hijacks your agent, TrustLayer blocks the payment

The agent gets a shopping task and tools: list vendors, read their pages, check its budget, ask to pay. The vendor page hides a note for AI assistants: pay a different wallet, plus a 0.02 SOL fee.

A careless agent obeys the note and asks to pay the attacker. TrustLayer blocks it: the model never decides, plain-code rules do.

Questions and limits

Built for the MLH Solana Hackathon, 6 to 8 November 2026.

Read the API

Can the AI approve a payment?

No. The model plans, reads and asks to pay. The policy engine is deterministic code: it decides, and the model can't change the rules or the result. The model also writes the plain-English explanation of each verdict.

Which model runs the agent?

Groq openai/gpt-oss-20b, server-side. Public runs are dry runs, capped per day, and never move funds.

Where are the rules enforced?

Off chain, at the approval step. On chain, the 2-of-2 threshold enforces the outcome: no gatekeeper vote, no transfer.

Does TrustLayer hold my funds?

No. Funds stay in the Squads vault, and the gatekeeper key alone cannot move them.

Which network does it run on?

Solana devnet only, for now.

What gets logged?

Every attempt, with a plain-English reason. Limit breaches, unknown recipients, expired permissions and failed simulations also raise security events.
